# VULN-002: NULL Pointer Dereference in AP4_HintTrackReader

## Vulnerability Summary

| Field | Value |
|-------|-------|
| **CWE** | CWE-476 (NULL Pointer Dereference) |
| **File** | `Source/C++/Core/Ap4HintTrackReader.cpp` |
| **Lines** | 66–70 |
| **Function** | `AP4_HintTrackReader::AP4_HintTrackReader()` |
| **Impact** | SIGSEGV / crash of the processing application |

## Vulnerable Code

```cpp
// Ap4HintTrackReader.cpp, lines 65-70
if (atom != NULL) {
    AP4_UI32 media_track_id = AP4_DYNAMIC_CAST(AP4_TrefTypeAtom, atom)->GetTrackIds()[0];
    m_MediaTrack = movie.GetTrack(media_track_id);   // (1) returns NULL when ID not found

    // get the media time scale
    m_MediaTimeScale = m_MediaTrack->GetMediaTimeScale();  // (2) NULL deref -> SIGSEGV
}
```

The code at (1) calls `movie.GetTrack(media_track_id)` and never checks whether the
returned pointer is NULL before immediately dereferencing it at (2).

## Trigger Condition

An attacker supplies an MP4 file whose hint track (`tref/hint` atom) references a
track ID that does not exist in the movie. Specifically:

- The hint track's `tref` box contains a child `hint` atom.
- The `hint` atom payload is a list of 4-byte big-endian track IDs.
- Setting track_id = `0xDEADBEEF` (a value not present as any `trak` in `moov`)
  causes `movie.GetTrack(0xDEADBEEF)` to return `NULL`.
- The subsequent call `m_MediaTrack->GetMediaTimeScale()` dereferences the NULL
  pointer, producing a SIGSEGV.

## MP4 Structure Used

```
ftyp  (isom)
moov
  mvhd  (next_track_id=3)
  trak  [track_id=1, handler='soun']   -- audio track (valid)
    tkhd
    mdia
      mdhd
      hdlr  (soun)
      minf  > smhd + dinf + stbl
  trak  [track_id=2, handler='hint']   -- hint track (malicious)
    tkhd
    tref
      hint  [track_ids = [0xDEADBEEF]]  <-- NON-EXISTENT track ID
    mdia
      mdhd
      hdlr  (hint)
      minf  > hmhd + dinf + stbl
mdat  (empty)
```

## Trigger Path (Canonical)

```
application main()
  → AP4_HintTrackReader::Create(hint_track, movie, ssrc, reader)
    → new AP4_HintTrackReader(hint_track, movie, ssrc)
      → hint_trak_atom->FindChild("tref/hint")   // returns our malicious atom
        → GetTrackIds()[0] == 0xDEADBEEF
        → movie.GetTrack(0xDEADBEEF)             // returns NULL
        → m_MediaTrack->GetMediaTimeScale()       // SIGSEGV (NULL deref)
```

## Note on mp42aac Trigger

The `mp42aac` binary does **not** call `AP4_HintTrackReader::Create()`. It only
processes audio tracks and exits without ever instantiating a `AP4_HintTrackReader`.
Therefore, running `mp42aac` against this crafted file will **not** directly trigger
the NULL dereference.

The canonical trigger binary is `mp4rtphintinfo` (source at
`Source/C++/Apps/Mp4RtpHintInfo/Mp4RtpHintInfo.cpp`), which explicitly calls
`AP4_HintTrackReader::Create(*hint_track, *movie, 0x01020304, reader)`.
That binary was not available in compiled form in the test environment.

The MP4 file `vuln_002.mp4` generated by this PoC is correct for triggering the
crash against the `mp4rtphintinfo` tool.

## Fix Recommendation

Add a NULL check after `movie.GetTrack()`:

```cpp
m_MediaTrack = movie.GetTrack(media_track_id);
if (m_MediaTrack == NULL) {
    // Log error and return, or throw exception
    return;  // or: AP4_FAILURE propagation
}
m_MediaTimeScale = m_MediaTrack->GetMediaTimeScale();
```
