# VULN 001 – AP4_NullTerminatedStringAtom Heap OOB Write (Integer Underflow)

## Vulnerability Summary

- **File**: `Bento4/Source/C++/Core/Ap4Atom.cpp`, lines 471–474
- **Function**: `AP4_NullTerminatedStringAtom::AP4_NullTerminatedStringAtom(AP4_Atom::Type, AP4_UI64, AP4_ByteStream&)`
- **CWE**: CWE-191 (Integer Underflow) → CWE-122 (Heap-based Buffer Overflow)

## Root Cause

```cpp
AP4_Size str_size = (AP4_Size)size - AP4_ATOM_HEADER_SIZE;  // line 471
char* str = new char[str_size];                              // line 472
stream.Read(str, str_size);                                  // line 473
str[str_size-1] = '\0'; // force null-termination           // line 474
```

`AP4_Size` is `uint32_t`. When `size == 8` (the atom header size), `str_size = 8 - 8 = 0`.
Then `new char[0]` returns a valid but zero-length heap allocation.
`str[str_size - 1]` = `str[0 - 1]` = `str[0xFFFFFFFF]` — an unsigned underflow.
This is a write to `str + 4294967295`, which is a massive heap out-of-bounds write.
ASAN detects this as `heap-buffer-overflow`.

## Trigger Condition

The factory at `Ap4AtomFactory.cpp:524` handles the `8id ` atom type
(`AP4_ATOM_TYPE_8ID_` = `AP4_ATOM_TYPE('8','i','d',' ')` = bytes `0x38 0x69 0x64 0x20`)
by constructing `AP4_NullTerminatedStringAtom`. No minimum-size guard exists before this
constructor call, so a size-8 box (header only, no payload) passes through.

## PoC File Structure

The crafted `vuln_001.mp4` contains:
1. **ftyp box** (16 bytes): standard file type box so the parser doesn't reject the file immediately.
2. **8id  box** (8 bytes): just the 8-byte header, no payload.
   - Bytes: `00 00 00 08 38 69 64 20`
