# VULN 001 – Integer Underflow in ReadChildren via Crafted 64-bit Container Atom

## Vulnerability

**File**: `Bento4/Source/C++/Core/Ap4ContainerAtom.cpp`  
**Function**: `AP4_ContainerAtom::Create()` (line 57) and constructor (line 154)

### Root Cause

`AP4_ContainerAtom::Create()` guards against undersized full atoms with:

```cpp
if (size < AP4_FULL_ATOM_HEADER_SIZE) return NULL;   // checks against 12
```

However, for a 64-bit-encoded full atom the actual header is
`AP4_FULL_ATOM_HEADER_SIZE_64 = 20` bytes (size_32 + type + size_64 +
version + flags).  When the parser encounters a `meta`/`odrm`/`odkm` atom
with `size_32 = 1` and `size_64` in the range `[12, 19]`, the guard passes
(e.g. `14 >= 12`), but the subsequent computation in the constructor:

```cpp
ReadChildren(atom_factory, stream, size - GetHeaderSize());
// size=14, GetHeaderSize()=20  →  14-20 = 0xFFFFFFFFFFFFFFFA (uint64 underflow)
```

passes approximately 18 exabytes to `ReadChildren` as `bytes_available`.

`GetHeaderSize()` for a 64-bit full atom returns:
```cpp
(m_IsFull ? AP4_FULL_ATOM_HEADER_SIZE : AP4_ATOM_HEADER_SIZE) + (m_Size32==1 ? 8 : 0)
//          12                                                   + 8              = 20
```

### Trigger Path

```
mp42aac main()
  └─ AP4_File(stream)
       └─ AP4_AtomFactory::CreateAtomFromStream
            └─ [reads size_32=1, type="meta", size_64=14]
                 └─ AP4_ContainerAtom::Create(META, size=14, is_full=true, force_64=true)
                      ├─ size(14) >= AP4_FULL_ATOM_HEADER_SIZE(12) → passes guard
                      ├─ AP4_Atom::ReadFullHeader(version=0, flags=0)
                      └─ new AP4_ContainerAtom(META, 14, true, 0, 0, stream, factory)
                           └─ ReadChildren(stream, bytes_available = 14-20 = 0xFFFFFFFFFFFFFFFA)
                                └─ Greedily parses child atoms far beyond declared boundary
```

### Alternative trigger: non-full `marl` container

`marl` is a non-full top-level-only container atom. `GetHeaderSize()` = 16
for a 64-bit non-full atom. Any `size_64` in `[8, 15]` underflows:

```
size_64=8:  8-16 = 0xFFFFFFFFFFFFFFF8
```

The factory code at line 768–771 allows `marl` with 64-bit encoding when
`GetContext()==0`, and the non-full branch of `Create()` calls the constructor
directly without a size guard.

## Expected Behavior

- **ASAN build**: The underflowed `bytes_available` causes `ReadChildren`
  to continue parsing far past the atom boundary.  Depending on what the
  parser encounters in the stream, this may trigger a heap-buffer-overflow
  or produce ASAN output due to an invalid read.
- **Release build**: The parser silently reads garbage data from outside
  the declared atom boundary, potentially enabling information disclosure
  or triggering undefined control flow.
