Reason no sanitizer fired:

   in unsigned integer wraparound (0xFFFFFFFE), which is DEFINED behavior in C/C++ for
   unsigned types. Standard -fsanitize=undefined does not instrument this case.
   The binary contains: __ubsan_handle_sub_overflow (signed only), no unsigned variant.

2. ASAN: The OOB read happens via a file stream abstraction (AP4_ByteStream::ReadUI16,
   CreateAtomFromStream). The data read is from a sequential file, not from a
   fixed-size heap buffer allocated for ipro's declared payload. ASAN instruments
   heap/stack/global buffer overflows, not logical bounds violations in streaming I/O.

Program behavior: exit code 1, message "ERROR: no audio track found" (expected for a
malformed MP4 with no audio track, not a sanitizer-triggered abort).
