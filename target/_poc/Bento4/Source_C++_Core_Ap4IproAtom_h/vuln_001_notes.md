# VULN-001: Integer Underflow in AP4_IproAtom Constructor

## Vulnerability Summary

**File**: `Bento4/Source/C++/Core/Ap4IproAtom.h`, constructor (line ~70)

**Type**: Integer underflow (unsigned wrap) leading to OOB read and unbounded atom parsing

## Root Cause

```cpp
AP4_LargeSize bytes_available = size - AP4_FULL_ATOM_HEADER_SIZE - 2;
```

- `AP4_FULL_ATOM_HEADER_SIZE = 12` (4-byte size + 4-byte fourcc + 1-byte version + 3-byte flags)
- `size` is `AP4_UI32` (unsigned 32-bit), promoted to `AP4_LargeSize` (uint64) after the subtraction
- The `Create()` factory guard only checks `if (size < 12) return NULL`, so `size == 12` passes
- When `size = 12`: `12 - 12 - 2 = 0xFFFFFFFFFFFFFFFE` (wraps as uint64 from 32-bit unsigned subtraction)

The resulting `bytes_available ~= 4GB` means every subsequent child atom size check passes unconditionally.

## Trigger Mechanism

The crafted MP4 places a `ipro` atom with its size field set to exactly 12 (the minimum that bypasses the guard) inside a `udta` container. The bytes that follow the 12-byte ipro header (but lie outside its declared boundary) are:

1. **entry_count** (2 bytes, `\x00\x01`): read by `AP4_UI16 entry_count; ReadUI16(entry_count)`
2. **sinf atom** (28 bytes): passed to `CreateAtomFromStream(stream, 0xFFFFFFFE, child)` by the loop

Since the stream is linear, the parser reads these bytes even though they fall outside the `ipro` box's declared size boundary. This constitutes an out-of-bounds read relative to `ipro`'s allocated/expected region.

## MP4 File Layout

```
ftyp (20 bytes): major_brand=mp42
moov (container):
  mvhd (108 bytes): minimal version=0 movie header
  udta (50 bytes):
    ipro_raw (12 bytes): size=12, triggers 12-12-2=0xFFFFFFFE underflow
    <OUTSIDE ipro boundary>
    entry_count (2 bytes): \x00\x01 = 1 entry
    sinf (28 bytes): parsed with ~4GB bytes_available
```

## Expected Behavior Under ASAN/UBSAN

- **UBSAN**: Reports `signed integer overflow` or `unsigned integer overflow` depending on build flags, or `runtime error: left shift of ... by ... places cannot be represented`
- **ASAN**: Possible heap-buffer-overflow if the parser allocates buffers based on the wrapped `bytes_available` value
- **Program behavior**: Reads beyond ipro's 12-byte footprint; may crash, produce garbled output, or trigger sanitizer traps
