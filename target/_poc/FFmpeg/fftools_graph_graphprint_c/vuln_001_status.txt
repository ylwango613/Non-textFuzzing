UNVERIFIED

Vulnerability: VULN 001 - NULL Pointer Dereference in print_filter() (CWE-476)
File: fftools/graph/graphprint.c lines 411-413, 443-446
Date: 2026-09-07

=== Code Defect Confirmed (Static Analysis) ===

The defect exists in print_filter() at two locations:

  Line 411-413 (inputs loop):
      AVFilterLink *link = filter->inputs[i];
      sec_ctx.context_type = av_get_media_type_string(link->type);  // NO NULL CHECK

  Line 443-446 (outputs loop):
      AVFilterLink *link = filter->outputs[i];
      sec_ctx.context_type = av_get_media_type_string(link->type);  // NO NULL CHECK

If filter->inputs[i] or filter->outputs[i] is NULL (unlinked pad), dereferencing
link->type causes a NULL pointer dereference.

=== Why It Could Not Be Triggered Dynamically ===

After extensive testing (12 filtergraph configurations), no crash was observed.
The protection is in libavfilter/avfiltergraph.c:graph_check_validity() which is
called at the START of avfilter_graph_config():

  for (j = 0; j < filt->nb_inputs; j++) {
      if (!filt->inputs[j] || !filt->inputs[j]->src) {
          // returns AVERROR(EINVAL) - config fails
      }
  }
  for (j = 0; j < filt->nb_outputs; j++) {
      if (!filt->outputs[j] || !filt->outputs[j]->dst) {
          // returns AVERROR(EINVAL) - config fails
      }
  }

If avfilter_graph_config() fails, ffmpeg_filter.c:configure_filtergraph() calls
cleanup_filtergraph() which calls avfilter_graph_free(&fgt->graph), setting
fgt->graph = NULL. Then at the finish: label:

  if (print_graphs || print_graphs_file)
      print_filtergraph(fg, fgt.graph);  // called with NULL graph

In print_filtergraph_single(), the filters section is guarded:
  if (graph) {  // NULL graph skips filter iteration
      for (unsigned i = 0; i < graph->nb_filters; i++) { ... }
  }

So the call path is:
  - Valid graph (all pads connected): print_filter() is called, all links non-NULL, no crash
  - Invalid graph (unlinked pads): config fails, graph is freed/NULL, print skips filters, no crash

=== Attempts Made ===

12 different filtergraph configurations were tested:
- Filters with AVFILTER_FLAG_DYNAMIC_OUTPUTS (split, select, ebur128, movie, channelsplit)
- Filters with AVFILTER_FLAG_DYNAMIC_INPUTS (bm3d, overlay)
- Configurations with partially-labeled outputs
- Invalid filter strings triggering mid-parse failures
- Format-change scenarios (filtergraph reinit)
- lavfi sources with split filters

None triggered the NULL dereference. All attempts either:
- Succeeded with a fully-configured graph (all links non-NULL)
- Failed at graph configuration and printed with graph=NULL (no filters printed)

=== Verdict ===

UNVERIFIED: The code defect (missing NULL check before link->type dereference)
exists in graphprint.c and could cause a NULL pointer dereference IF a filter
graph with unlinked pads is ever passed to print_filter(). However, under
normal ffmpeg operation, avfilter_graph_config()'s graph_check_validity() step
prevents any graph with unlinked pads from being configured, and print_filtergraph()
is never called with such a state from command-line usage patterns.

The vulnerability would require: (a) bypassing graph_check_validity, (b) a race
condition between graph modification and printing, or (c) internal API misuse.
None of these are achievable via normal command-line media file processing.
