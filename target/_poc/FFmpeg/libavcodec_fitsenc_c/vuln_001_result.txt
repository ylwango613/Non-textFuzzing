=== Mathematical Analysis ===
FFmpeg's av_image_check_size2 enforces: (8w+1024)*(h+128) < INT_MAX
This implies: 8*w*h < INT_MAX
Therefore: max(bitpix/8 * w * h * naxis3) <= 8*w*h < INT_MAX = 2,147,483,647
So NO supported pixel format can overflow int32 in the encoder via standard pipeline.

The closest case (GBRAP16BE): max 8*wh = 2,147,483,640 (margin of only 7 below INT_MAX).
