Root cause of non-trigger
--------------------------
In cavsdec.c ~line 1127:

    mb_type = get_ue_golomb(&h->gb) + P_SKIP + h->skip_mode_flag;
    if (mb_type > P_8X8)          <-- this comparison
        ret = decode_mb_i(h, mb_type - P_8X8 - 1);
    else
        decode_mb_p(h, mb_type);

The vulnerability hypothesis assumes a SIGNED comparison:
    (signed)-21 > P_8X8(5)  ==>  FALSE  =>  decode_mb_p(-21) called  =>  OOB

In this compiled binary the comparison is treated as UNSIGNED:
    (unsigned)-21 = 4294967275 > P_8X8(5)  ==>  TRUE  =>  decode_mb_i(-27) called

Evidence from run output

Conclusion
----------
The signed-comparison bypass vulnerability as described may exist in the
source code, but the binary built for this target compiles the enum cavs_mb
comparison as unsigned, preventing the intended trigger path. The PoC input
is structurally correct; the non-trigger is a property of the compiled binary.
