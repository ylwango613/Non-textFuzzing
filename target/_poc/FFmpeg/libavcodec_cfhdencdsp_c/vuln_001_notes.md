# VULN 001 – Heap Out-of-Bounds Read in `filter()` (libavcodec/cfhdencdsp.c)

## Summary

A heap out-of-bounds read exists in the `filter()` function of the CFHD encoder
DSP implementation (`libavcodec/cfhdencdsp.c`, lines 31-46).

## Root Cause

`filter()` unconditionally accesses:

```c
input[4 * in_stride]   // line ~40
input[5 * in_stride]   // line ~41
```

…and also accesses negative indices in the tail block (e.g. `input[-in_stride]`).
There is no guard that checks whether `len >= 6` before performing these reads.

## Trigger Condition

When encoding a 16-pixel-wide YUV422P10LE video with the CFHD encoder, the
Discrete Wavelet Transform (DWT) is applied recursively. At the deepest DWT
level:

- **Chroma (U/V) planes**: horizontal width = 16/2 = 8, after DWT level 1 → `len = 4`, after level 2 → `len = 2`
- **Luma (Y) plane**: horizontal width = 16, after DWT → `len = 4`

Both `len = 2` and `len = 4` are less than 6, so the filter reads `input[4]`
and `input[5]` (and negative indices) beyond the allocated buffer.

## PoC Input

- Format: raw YUV422P10LE
- Dimensions: 16×32 pixels (one frame)
- Generated by: `vuln_001_gen.py`

## Trigger Command

```bash
ffmpeg -f rawvideo -pixel_format yuv422p10le -video_size 16x32 -framerate 1 \
  -i vuln_001_input.yuv -c:v cfhd -f null -
```

## Expected ASAN Output

With AddressSanitizer enabled, the run should produce a report similar to:

```
ERROR: AddressSanitizer: heap-buffer-overflow on address ...
READ of size 2 at ...
#0 filter libavcodec/cfhdencdsp.c:40
```
