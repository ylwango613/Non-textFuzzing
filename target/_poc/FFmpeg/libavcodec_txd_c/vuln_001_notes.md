# VULN 001: Heap OOB Write in TXD DXT1 Decode — Non-Multiple-of-4 Height

## Summary

- **CWE**: CWE-122 (Heap-based Buffer Overflow)
- **Location**: `libavcodec/txd.c` `txd_decode_frame()`, delegating to `texturedsp.c` `dxt1_block_internal()`
- **Affected formats**: DXT1 (`d3d_format=0x31545844`) and DXT3 (`d3d_format=0x33545844`)

## Root Cause

`txd_decode_frame` at line 94 calls `ff_set_dimensions(avctx, w, h)` with the raw height (e.g., `h=1`). Then `ff_get_buffer` at line 100 allocates exactly `linesize × h` rows of RGBA pixel data.

The DXT1 decoding loop (lines 124–130) iterates `for (j = 0; j < avctx->height; j += 4)`, and for each iteration calls `dxtc.dxt1_block(p, stride, gb.buffer)`. The `dxt1_block_internal` function unconditionally writes **4 complete rows** of 4 pixels each (16 RGBA bytes per row) starting at pointer `p`.

When `h=1`, only 1 row is allocated. The block decoder writes rows 1, 2, and 3 past the end of the allocated buffer, causing a **heap buffer overflow of 3 × linesize bytes**.

## Trigger Conditions

| Field       | Value              | Reason                                      |
|-------------|-------------------|---------------------------------------------|
| platform_id | 8 or 9            | Passes version check (line 61)              |
| depth       | 0x10 (16)         | Selects DXT code path (line 70)             |
| d3d_format  | 0x31545844 (DXT1) | Selects dxt1_block (line 123)               |
| width       | 4                 | One DXT column block (4 pixels wide)        |
| height      | 1                 | NOT divisible by 4 → only 1 row allocated   |
| data_size   | 8                 | One DXT1 block (8 bytes for a 4×4 block)    |

## Impact

The overflow writes attacker-controlled DXT1 pixel data approximately 3 × linesize bytes past the end of the allocated frame buffer. In an adversarial context this could allow heap metadata corruption or, with a heap spray, code execution.
